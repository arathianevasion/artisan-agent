Review: Weekly CSV export slice

review-gateslice gate Engineering role · blocks #44 Email the export, #45 Export settings · run 2026-11-10-a

Problem

A user can download one week of time entries as a CSV that opens cleanly in a spreadsheet. From the spec Timesheet export, acceptance criteria:

  1. The export contains every entry in the chosen week, and nothing outside it.
  2. The file opens in Numbers and Excel with one row per entry and correct columns.
  3. The download button is disabled when the week has no entries.

Solution

Three tickets merged: #41 Export endpoint, #42 CSV formatter, #43 Download button. Along the way the agents decided:

  • Weeks start on Monday (ISO), not the user's locale. taste · product
  • Durations are exact minutes, not rounded to a quarter hour. taste · product
  • The CSV is built in memory, capped at 10,000 rows, rather than streamed. engineering

They were unsure about:

  • An entry that crosses midnight between Sunday and Monday: it's counted in the week it started. No test covers this.
  • Notes containing Windows line endings (\r\n): only \n was tested.

Guardrails applied: no new dependencies without approval (product), so the formatter is hand-written; one PR per slice (individual).

Verification

Check these yourself (about 5 minutes):

  1. Run pnpm dev, log three entries this week (one crossing Sunday midnight), click Export. Expect three rows; the midnight entry lands in this week.
  2. Open the file in Numbers. Expect columns Date, Project, Minutes, Note.
  3. Add a note with a comma and a line break, export again. Expect it in one cell.
